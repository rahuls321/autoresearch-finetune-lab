LazyDecider

How an open-weight agent fine-tuned a decision model for me — proposing configs, pruning the losers, keeping only winners — while I slept.

🦥 Gemma 4 E4B proposes → ✂️ ASHA prunes → ✅ keep / ↩︎ revert → 🔬 Tinker confirms

Local · open weights · sealed test · ~$0 on a laptop

The ten-minute job I refused to do again

Hyperparameter babysitting:

  • change the learning rate → kick off a run → stare at the loss curve
  • change the LoRA rank → repeat → fall asleep at the desk

So I automated it. The search runs overnight, for free, on my own laptop. I wake up and read a report.

The task — typed decisions

A model reads a case and makes a calibrated accounts-payable style call across 4 domains, scored against a teacher consensus (gold).

DomainCasesWhat the model decides
invoice_processing100approve / review an invoice vs its PO
customer_service100route / escalate a ticket
security_incidents100triage severity & response
agent_trace_observability100flag anomalous agent traces

Metric that matters: KL from gold (distribution match), not just top-1 accuracy.

The model we fine-tune

  • Base: Qwen3.5-0.8B (open weights)
  • + Clef joint-decision head — emits a probability over all decisions
  • Trained with Unsloth, LoRA on an 18 GB Mac (MLX)
  • Two knobs the agent plays with:
  • head-only vs unfreeze backbone (LoRA)
  • LoRA rank/alpha, LR, label smoothing, weight decay, dropout, epochs

Why ASHA — don't waste the night on losers

Asynchronous Successive Halving: evaluate at rungs, prune the bottom performers early, let the promising runs train longer.

Rung (step)What happens
20first checkpoint — obvious failures killed here
60bottom percentile pruned
140survivors continue
240full run — only the best reach here

A bad config costs minutes, not the whole night.

The “can’t cheat” part

Early on, the loop found a “winner” suspiciously fast — a too-small validation subsample let a lucky run look great. The agent wasn’t cheating; it was optimizing the number I gave it.

  • 🔒 Sealed test — only its SHA-256 is committed; the worker can’t read the cases
  • 📏 Scorer copies the dataset’s grading arithmetic verbatim
  • 💸 Worker strips TINKER_* from env — the free local loop can’t spend a cent
  • 🧊 Every finalist’s config is committed to git before its one-shot sealed read

Why open innovation matters here

  • 🦥 Agent + model are both open weights → hundreds of reasoning calls a night cost $0
  • 🔓 The model is yours → run it offline, push the adapter to HF, fork the recipe
  • 🔍 Guardrails are auditable → “can’t cheat” is only credible when anyone can read the sealing logic

A closed API couldn’t give me all three: free overnight reasoning, full ownership, and verifiable integrity.

The lazy payoff
